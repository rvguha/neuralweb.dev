Life of a query: the ARD agent finder

Design document, 2026-10-09. Covers ard-finder as deployed in revision ard-00049-ciq (index of 24,827 entries). Every claim carries a file and line reference; numbers marked "measured" were read from the running service the same day. Sibling documents: NeuralKG2 (the caller that depends on ARD most), QDRSS (QDRSS), NLWeb samples (the NLWeb samples).

0. How to read this

ARD (the Agent Resource Discovery finder, at ard.neuralweb.dev) answers one question: which published tables describe this quantity? You give it a description ("median household income", "gdp india") and it returns the OKF table documents that describe it, ranked, each naming a variable, a source and how to ask for it. It never fetches data itself.

Callers: NeuralKG2 (one search per piece of data a question needs, plus exact /variable and /variables lookups), the ARD browser page at neuralweb.dev/4dc/ard/, and any MCP client (POST /mcp).

Words used throughout

  • Entry / document / leaf: one OKF markdown file describing one published table or variable from one source. For Data Commons, one (variable, source) pair.
  • Source family: the publisher a document belongs to (datacommons, sec-edgar, census, worldbank, ...). The five BigQuery directories collapse into one family, bigquery.
  • Phrasing: one text the caller asks about. A request carries up to 4; ARD adds a place-stripped version of each.
  • Pool / head / slice: the candidates gathered by embedding similarity, and the first part of them that the model actually sees.
  • Rerank: scoring candidates 0 to 100 with a model. The only model judgment on the search path besides the embedding.
  • Family (of a Data Commons variable): (populationType, measuredProperty, statType), with its constraints (the dimensions it is split by: age, race, gender...). Used by /variables.

The service is one Starlette app on Cloud Run (ard, us-central1). The index and the leaf files ship inside the image; there is no database. Models: embeddings openai/text-embedding-3-small (1536 dimensions), rerank openai/gpt-oss-20b, both through OpenRouter.

2. The life of a search

ARD answers one question: which published tables describe this quantity? It never fetches data. Its output is a ranked list of OKF table documents, each naming a variable, a source, and how to ask for it. Source: ard-finder (agent_finder.py, registry/index.py, registry/places.py, filters.py, llm.py).

2.1 What exists before any query (the build)

The index is built offline by registry/index.py:build (207-304) and shipped inside the image as registry/current/.

  1. Collect every *.md under sources/ and corpora/gcp-bigquery/okf/ whose front matter has representativeQueries (_collect_docs, 155-198). These leaves are written by the tools/gen_*_okf.py generators from each publisher's catalog (Data Commons variables, SEC filings, World Bank indicators, Census tables and so on).
  2. Embed one text per entry (index_text, 117-128): title, all representative queries, "Describes {scope}" (the source's entity type), then the full description, joined with ". ". Model openai/text-embedding-3-small, 1536 dimensions, 8000-character input cap.
  3. Publish vectors.npy (float16, 76 MB on disk, about 150 MB as float32 in memory), meta.json (26.6 MB) and manifest.json to registry/current. Vectors are reused when an entry's sig (md5 of text plus model) is unchanged, so a rebuild embeds only what changed. Batches of 96 are checkpointed.

Size on 2026-10-09: 24,827 entries. Data Commons 11,595; SEC EDGAR 8,096; Census 2,000; World Bank 1,498; UN SDG 713; BigQuery public 356 and marketplace 240; Treasury 186; nonprofit 990 57; CDC PLACES 40; about 40 others.

At server start (agent_finder.py:841-853) the service verifies the release is current, loads the vectors and metadata (index._store), projects every row into an ARD entry (_catalog), and builds two exact-lookup tables from the Data Commons leaves (_variable_index, 631-653): variable -> leaf paths and variable -> family where a family is (populationType, measuredProperty, statType, constraints). Those two tables are what /variable and /variables read. If no model credentials are present, startup fails (llm.py:47).

There is no authentication. CORS allows any origin. Body limit 64 KB (413 above). /search has a per-IP daily quota of 10,000 held in process memory (429 with Retry-After); the quota is charged before the request is validated.

2.3 A /search request, step by step

NeuralKG2 sends (neuralkg2/catalog.py:160-170):

{"query": {"text": "Find tables for: gdp india. Background only, not the search: the user's full question is \"What is India's GDP?\".",
           "texts": ["gdp india", "What is India's GDP?", "gdp"]},
 "pageSize": 10, "rerank": true, "sources": ["datacommons"]}

Step 1: validate (agent_finder.py:766-793). query.text must be a non-empty string; query.texts a list of 1 to 4 non-empty strings (default [text]); pageSize clamped to 1-100; sources/excludeSources lists of at most 50 names that must exist (400 with the valid names otherwise); query.filter may use publisher, type, tags (other keys are reported back in filter.ignored). Values in one key are ORed, different keys ANDed (filters.py).

Step 2: phrasings (index.py:687-698). The caller's texts come first. For each, places.strip (places.py:98-101) adds a version with places removed ("gdp india" becomes "gdp") from a gazetteer of US states, countries, large cities, demonyms and "X County"-style patterns. Reason: documents describe measures, not places, and a place in the query drags in any document that merely mentions it. At most 8 phrasings result. No model rewrites the query.

Step 3: embed and score (search_many_async, 797-857). All phrasings are embedded in one call and L2-normalised. Each entry's score is its maximum cosine similarity over the phrasings (sims = vecs @ q.T, 24,827 rows, numpy). Entries are walked in descending score, the request's filters applied, until about 150 (ARD_PREFILTER_MAX) are collected. Each carries embed_score = round(score*100, 1).

Step 4: shape the pool before the model sees it. This is the part that decides recall.

Rule Constant Effect
Adaptive slice PREFILTER_SLICE 30, band 5 points, cap 150 the head is at least 30 and as many as sit within 5 points of the top score
Examined cap PREFILTER_EXAMINED_MAX 120 never rerank more than 120
Each phrasing's best PER_PHRASING 6 each phrasing's six best tables are promoted into the head if they were below the cut
Each source's best PER_SOURCE_POOL 3 every source family gets at least its three best into the head

The per-phrasing rule exists because a place-bearing phrasing and the stripped phrasing find different tables; keeping each phrasing's best means a table that either finds survives. The per-source rule exists so a large source (Data Commons has 11,595 entries) cannot push every other source out of the head.

Step 5: rerank with a model (_rerank_by_source, 860-890). Candidates are grouped by source family in order of first appearance; the first 5 families are scored, one model call each, in parallel. The first group is scored alone; the other four are prefixed with the first group's top 2 candidates as anchors (their scores are discarded) so a weaker source is not graded on a curve.

  • Prompt (_rerank_messages, 474-495): judge each numbered card by title, scope and example questions; prefer recall, keep siblings and alternative definitions; return {"ranked":[{"i":n,"score":0-100}]}; score every candidate; never return an empty list.
  • Card (_card, 418-434): title, covers: <scope>, up to 6 people ask: queries. The description is left out unless ARD_RERANK_DESC=1.
  • Model RERANK_MODEL, openai/gpt-oss-20b in production. Temperature 0, JSON mode, reasoning effort low, provider sort throughput.
  • Output budget (_rerank_budget, 403-415): max(400, 16*n + 300) + 1500 tokens.
  • Retries (llm.py:431-489): up to 4 attempts on 408/409/429/5xx with Retry-After or min(30, 2**attempt) back-off; an empty completion retries with max_tokens doubled, up to 8000 (this was the cause of the slow "choosing tables" step fixed on 2026-10-08, when a reasoning model spent its whole budget thinking). Per call 120 s; the whole query has a 180 s deadline.
  • Parse (_ranked_candidates, 498-513): only the first k items; an item needs an integer i in range and a numeric score; bad items are skipped. A result is eligible when score >= 50 (ARD_MIN_RERANK_SCORE).

Step 6: merge (_source_first, 653-663). Eligible results are ordered with the best result of each source first (up to 5 sources), then the rest by score, cut to pageSize. The order is therefore not purely by score: it guarantees breadth across sources.

Step 7: widen when nothing qualifies (836-857). If no candidate scored 50 or more, the service looks at how spread the embedding scores of the head are. A spread (standard deviation) of 3.0 or more means the head already separates good from bad, and the answer is "no match". A narrow spread means the embedding cannot tell and the answer may be deeper, so it scores further windows of 30 up to 120 examined, stopping when something qualifies.

Step 8: respond. Each hit becomes a full ARD entry read from the leaf file (_entry_from_meta, 230-280): identifier (a URN urn:air:<publisher>:okf:<source>.<leaf>), displayName, description, representativeQueries, tags, the okf:* terms of the leaf merged over its source's _access.md (variable, facet, unit, populationType, measuredProperty, statType, constraints, coverage, latest observation, access operations), the markdown body, and score. The envelope also carries usage: model calls, tokens, dollars and a per-stage and per-model breakdown (llm.Ledger).

2.4 What NeuralKG2 does with the result

RemoteCatalog._search (neuralkg2/catalog.py:160-200) validates the shape strictly (a malformed response is a provider failure, never an empty result), maps each entry to a Resource through the directories table in ard-gcp.json (datacommons to the Data Commons plugin, and so on; an entry with no plugin becomes ard:<family> and is handled by the generic source), and turns no_match into an empty result. If the reranked search comes back empty, NeuralKG2 retries once with rerank: false (catalog.py:131-138) and the plugins judge every document themselves.

2.5 Where ARD is deterministic and where it is not

Deterministic: validation, filters, place stripping, the embedding walk, the slice, per-phrasing and per-source promotion, source-first ordering, the score threshold, the widening rule, and every /variable and /variables answer. Model-driven: the 0-100 rerank score (which decides what appears at all) and the embeddings themselves.

2.6 Failure behaviour

Condition Response
No candidate clears 50 200, results: [], eligibility: {status: "no_match", threshold, topScore}
Rerank of the first group fails 503 relevance_scoring_failed (embedding order is deliberately not substituted)
Query deadline 504 query_cancelled
Embedding or credential failure unhandled, 500, no usage
Daily quota 429

Silent behaviours worth knowing (all visible in the code, none visible in a response): sources beyond the fifth are never scored; a failure in any non-leading group drops that source without a signal; malformed ranking items are skipped without notice; rerank: false returns embedding order on a different score scale without saying so; a wide first slice short-circuits widening even when the answer is deeper; broken leaf files lose their okf:* terms without an error.

5. Invariants

  1. A failed rerank is never replaced by embedding order. The leading group's failure is a 503 that says so (agent_finder.py:795-823).
  2. Breadth across sources is guaranteed before depth by score: each source's best three enter the head, and each of up to five sources leads the results with its best table (index.py:632-663).
  3. Either phrasing finds a table: a table found by the place-bearing or the place-stripped phrasing stays eligible (_head_with_each_phrasing).
  4. /variable and /variables are exact: no embedding, no model (agent_finder.py:656-699).
  5. Names are checked: an unknown source or publisher is a 400 listing the valid ones, never an empty result that looks like "no match" (filters.py).
  6. The release is verified at start: a stale or incomplete index refuses to serve (agent_finder.py:893-899).

6. Open issues

  • Sources beyond the fifth are never scored, and a failed non-leading rerank group drops its source with no signal in the response.
  • Malformed ranking items are skipped without notice; rerank: false returns embedding order on a different score scale without saying so.
  • A wide first slice (standard deviation of 3.0 or more) stops the search with no_match even when the answer sits deeper.
  • The daily quota is charged before the request is validated, and it is per process (it resets on restart and is per replica).
  • Embedding or credential failures are unhandled and return 500 with no usage in the body.
  • Place stripping is a regex and gazetteer; it misses places not listed and can strip words that are also names ("Georgia", "Jordan", "Austin"). strip_capitalized exists but is unused in production.
  • Leaf-file errors are swallowed (_leaf_fm, _access_fm return {}), so a broken leaf silently loses its okf:* terms.
  • Building search results reads leaf files synchronously inside the event loop; time grows with pageSize.
  • /health and /stats counters are per instance and reset on restart.
  • /healthz is answered by Cloud Run's front end, not the app; use /health.
